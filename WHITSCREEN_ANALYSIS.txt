CRITICAL FINDINGS
================================================================================

1. PRIMARY ISSUE: spawn('script', ...) Crashes Renderer
   Location: src/main/services/onboarder.ts, Line 503-565, runEmbeddedMacPtyScript()
   
   Code:
   ```
   const child = spawn('script', ['-q', '/dev/null', 'bash', scriptPath], {
     env  // Full Electron environment
   })
   ```
   
   Why It Fails:
   - 'script' is a POSIX utility for recording terminal sessions, NOT running bash
   - Creating pseudo-terminal (PTY) has resource issues in Electron
   - Full environment passed includes V8 heap references causing conflicts
   - Process crashes with SIGKILL (signal 9) → kills renderer process
   - Result: Blank white screen with no error message

2. SECONDARY ISSUE: External Terminal Fallback (Lines 439-501)
   Location: src/main/services/onboarder.ts, runMacTerminalScript()
   
   Code:
   ```
   spawn('osascript', [
     '-e', 'tell application "Terminal" to activate',
     '-e', `tell application "Terminal" to do script "bash \\\"${scriptArg}\\\""`
   ])
   ```
   
   Why It's Broken:
   - Opens external Terminal.app window
   - Steals focus from Electron app
   - User sees "white screen" because Terminal app hides Electron
   - No terminal output visible in app UI
   - Cannot detect QR code scanning success in app
   - This is the fallback when embedded terminal crashes

3. RACE CONDITION: Window Destruction Safety (Lines 121-186)
   Location: src/main/services/onboarder.ts, createTerminalOutputEmitter()
   
   Issue:
   - Window could be destroyed between isDestroyed() check and send() call
   - If renderer crashes, cleanup doesn't happen properly
   - Timers fire after window destruction

4. MISSING TIMEOUT: No Process Timeout Protection
   - runEmbeddedMacPtyScript() has no timeout
   - Hung process blocks indefinitely
   - Eventually forces OS to SIGKILL renderer

5. ENVIRONMENT POLLUTION: Full Electron Environment Passed
   - Variables like V8_PLATFORM_ARCH, NODE_CHANNEL_FD cause conflicts
   - 'script' command expects simple shell environment
   - Electron-specific vars break POSIX tool expectations

RECOMMENDED SOLUTION
================================================================================

OPTION A: Replace 'script' with direct bash (RECOMMENDED - SIMPLEST)

Current (Broken):
  spawn('script', ['-q', '/dev/null', 'bash', scriptPath], { env })

Fixed (Solution):
  spawn('bash', [scriptPath], {
    env: {
      PATH: env.PATH ?? process.env.PATH,
      npm_config_prefix: env.npm_config_prefix,
      npm_config_cache: env.npm_config_cache
    }
  })

Advantages:
✅ No PTY complexity
✅ Direct process control
✅ Proper signal handling
✅ Clean stdout/stderr
✅ Works on all platforms
✅ Minimal code changes
✅ No new dependencies

Implementation Impact:
- createTerminalOutputEmitter() unchanged (works perfectly)
- EmbeddedTerminal.tsx unchanged
- useTerminalStream.ts unchanged
- Only change: replace spawn('script',...) with spawn('bash',...)
- Remove fallback to runMacTerminalScript() entirely

─────────────────────────────────────────────────────────────────────────────

OPTION B: Use node-pty library (Alternative - Better terminal support)

Advantages:
✅ True PTY support (colors, interactive commands)
✅ Better for complex shell interactions

Disadvantages:
❌ External dependency (npm install node-pty)
❌ Native compilation required
❌ More complex implementation

─────────────────────────────────────────────────────────────────────────────

BOTH SOLUTIONS:
1. Add timeout protection (5+ minutes)
2. Better error handling with try/catch/finally
3. Only pass necessary environment variables
4. Never open external Terminal.app
5. User sees progress in embedded terminal
6. Can detect QR code scanning patterns
